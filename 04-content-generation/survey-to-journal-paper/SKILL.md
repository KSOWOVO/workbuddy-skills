# 问卷数据 → 中文期刊实证论文

## 两种模式（先判断是哪一个）

| | 模式 A：写新论文 | 模式 B：融进既有论文 |
|---|---|---|
| 场景 | 「把数据写成一篇论文」 | 「这篇文章不能改，把数据加进去」 |
| 原文 | 只作文风/格式参照 | **就是交付物本体，只增不改** |
| 关键动作 | 搭骨架、写假说 | 设计"新增节→回应原文章节"映射表、章号顺延 |
| 交付 | 单份 | **双版本**（融合版 + 附录版） |
| 详见 | 本文件正文 | `references/merge-into-existing-paper.md` |

模式 B 特有的硬约束：md5 锁定源文件、章号顺延的 run 拆分坑、附录模式"后文"指代漂移、
分号必须为 0。**动手前先读那份 reference。**

## 适用判断
用户手上有**已跑完的问卷统计结果**（信效度、EFA、SEM、中介效应等），要产出**正式论文初稿**，
且给出了「文风参照物」和「格式参照物」。这是文档生产任务，不是数据分析任务——数值一律照抄已有统计结果，
**不要重跑、不要"修正"数字**；只在需要补样本画像等缺失统计量时才重算，并交叉验证一致性。

## 三件套输入（缺哪个先要哪个）
| 角色 | 作用 | 提取方式 |
|---|---|---|
| 统计数据 | 所有表格数值的唯一来源 | docx：`python-docx` 读 paragraphs + tables；xlsx：`openpyxl` |
| 文风底座 | 句式、术语、连接词、标题命名 | 精读全文，提炼"语气指纹"（见下） |
| 格式模板 | 章节骨架、假说编号法、表注格式、参考文献体例 | 优先读 PDF，看目录级结构与表注写法 |

## 执行步骤

### 1. 拆文风（先做，最重要）
从底座论文里摘出**可复用的语言特征清单**，落到写作时逐条套用：
- 段落长度（多长一段）、句长（长句/短句比例）
- 高频连接词与话术（如「具体而言」「与之相呼应」「究其原因」「据此」「基于此，本研究认为」）
- 领域术语库（作者反复用的那批词，要复现）
- 标题层级与命名习惯（"1.1" vs "（一）1."）
- 引用体例（`[n]` 还是 `(作者，年份)`）——**按模板为准，不是按底座**

### 2. 对齐模型（不可自作主张）
若用户给了理论模型图/变量清单，**严格按它的潜变量与路径条数编号假说**。
不要额外增加假说编号（中介效应可作机制分析，不单列 H 编号）。
先把模型写成一张假说—路径对照表，后续所有章节共用这套编号。

### 3. 处理数值
- 逐一核对统计结果的均值、α、KMO、载荷、路径系数、拟合指标
- 用 Python 独立重算能重算的（如潜变量均值）做交叉验证
- **重点标注"不显著"的路径**——那是论文的理论增量所在，必须诚实报告并给出学理解释，
  不要粉饰成显著。同时用宽松检验（如多元回归）做稳健性对照，说明为何以严格检验为准。

### 4. 建骨架（照模板，不照底座）
典型六段式：`引言 → 文献回顾与研究假说 → 研究设计 → 实证分析结果 → 研究结论与启示 → 参考文献`
- 引言要含「三重现实困境 + 三方面文献不足 + 四点边际贡献」
- 假说段用「据此提出如下假说。**H1：** ……」句式
- 结论用①②③④编号 + 「第一/第二/第三…」建议
- 末尾附英文标题 + Abstract + Keywords（若模板有）

### 5. 编译 DOCX
用 `scripts/` 下的工具，或直接复用本 skill 沉淀的做法：
- 正文 markdown → docx（`build_docx.py` 模式：逐行解析 md，遇表占位符插三线表）
- 三线表：表级全边框 none，首行单元格 top=12(border sz) + bottom=6，末行 bottom=12
- 中文字体必须同时设 `w:ascii/hAnsi/eastAsia`，否则中文回退成默认字体
- 理论模型图用 matplotlib 画（`font.sans-serif = ["Microsoft YaHei"]`），存 PNG 再 `add_picture`

### 6. 交付前自检（必做）
回读 docx 校验：段落数、表格数、图片数、参考文献条数、假说段数、
**引号是否为中文弯引号**、章节顺序是否与模板一致。

## 关键坑（详见 references）
1. **中文引号会被转成直引号**：任何写入 md/源码的中文引号都要在编译前后置替换回 `""`，
   且**绝不能用"按行内引号成对替换"去处理 Python 源码文件**（会改掉字符串定界符）——
   中文内容一律用单引号做 Python 定界符。
2. **本机 bash PATH 可能损坏**（`ls`/`grep`/`head`/`tail` 找不到）→ 全程用绝对路径调 Python，
   列目录改用 Python `os.walk` 或 PowerShell。
3. **python-docx 没有竖排合并的现成 API**，用 `cell_a.merge(cell_b)` 做纵向合并。
4. 三线表**不能靠样式名**，必须手写 `w:tblBorders` / `w:tcBorders` XML。
