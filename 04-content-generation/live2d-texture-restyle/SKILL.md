# Live2D 皮套改造 + 画风对齐

## 何时用

- 手上有一套 Live2D 模型（`*.moc3` + `*.model3.json` + `texture_*.png`），想改成自己的 OC
- 已经用 AI（Gemini / 即梦 / SD）出了图，但**画风和原画不一致**（"看着不像同一个画师画的"）
- 需要把生成结果**套回原模型**能直接跑

## 一、硬约束：Live2D 能改什么、不能改什么

先读 `*.model3.json` 找到贴图路径，然后：

```
*.moc3  ← 二进制，锁死一切：网格顶点、变形器、参数绑定、UV 坐标
  └── texture_00.png  ← 只是"上色用的皮"，可替换
```

**换贴图 ≠ 模型更新。** 模型不会重新识别新图，只会把**新图上原坐标位置的像素**贴到对应网格上。所以：

| 能改 | 不能改 |
|---|---|
| 配色、衣服花纹、妆容、瞳色、发色 | 发型轮廓、脸型、姿势 |
| 加纹理/图案（不改变外形） | 增减部件、改部件位置 |
| 部件在**自己坐标框内**的重绘 | 部件越框（会撕裂） |

⚠️ 重绘时**部件必须留在原坐标框内**，画布尺寸必须保持原尺寸。

### 最容易忽略的硬约束：新部件的「剪影」做不出来

贴图里大片空白区域**看起来可以随便放新东西，其实不行**——只有网格 UV 实际覆盖到的像素才会显示。
所以**加一件新衣服（外套/披风/大裙摆）时，它的轮廓不能超出已有网格的形状**。

判断方法：把 `part_segment` 出的区域裁出来，只看 alpha 通道 → 得到该网格的**剪影**。
以实测的 `yoyo` 为例：
- 身体网格 = 一个「脖子 + 躯干 + A 字裙（波浪下摆）」的剪影，**没有外套形状**
- 手臂 = 两条带尖角的长条（袖 + 手），所以袖子**做不出蓬松大袖**
- 结论：**外套只能"贴在"原轮廓内画** —— 能做到"敞开外套 + 中间露裙子"的视觉（在同一轮廓内两侧画门襟、中间画裙），
  但做不到 oversized 飘逸大摆。

**想真正加一个超大外套**，只能进 Live2D Cubism Editor 加网格——那是重做模型，不是换贴图。

### 想保留原脸？直接别碰脸的分区

脸型由 moc3 网格锁死，**无论贴图怎么改脸型都是原来的**。而脸的五官是独立贴图岛
（脸底色 / 左眼 / 右眼 / 眉 / 嘴，通常还各有独立的腮红、闭眼 `< >` 形状件）。

所以「我要原来的脸」的正确答案是：**把这几个分区原样保留，不重绘**。
这比让 AI 重画一张脸更准，也省掉一整轮返工。拼图时 `reassemble.py` 会自动沿用缺失部件的原图。

## 二、流程

```
① 拆贴图分区   → part_segment.py，产出「标注图 + 分区清单 + 单部件裁剪」
② 量化原画风   → style_probe.py，测出明度/饱和/线条/主色
③ 写画风约束提示词 → 把②的数值写成 prompt 硬约束 + 上传画风样板图
④ AI 出图 / 逐区重绘 → 你或用户操作（产出 concept 设计图）
```

### ① 拆贴图分区

```bash
python scripts/part_segment.py <texture_00.png> <outdir>
```
输出：`标注图.png`（带编号+名称+坐标框）、`分区清单.json`、`parts/<编号>_<名称>.png`

拿到标注图后**务必肉眼核对**：自动分块只是辅助，部件语义（哪块是刘海、哪块是尾巴）要人判断，并把坐标写进一个固定清单后续复用。

**⚠️ 别靠肉眼猜部件归属——用「着色诊断法」确证。**

自动分块的语义很容易猜错。**实测翻车**：以为「身体+裙」是一个岛，改完渲染才发现 **裙子是另一个独立的岛**，
结果衣服换了、裙子还是旧的。靠裁剪看形状看不出来。

做法（一次渲染认全所有岛）：
1. 对贴图做 alpha 连通域，给**每个岛填一个高区分度的纯色** → `debug_texture.png`
2. 用它替换模型贴图，**渲染一次**（见 ⑥ 本地渲染）
3. 按颜色反查每个岛出现在身体的哪个位置 → 得到确凿的「岛 ↔ 部位」对照表

脚本：`scripts/island_diagnostic.py`（生成着色图）+ `scripts/island_legend.py`（从渲染图反查对照表）


### ② 量化原画风（本 skill 的核心）

```bash
python scripts/style_probe.py <原贴图或原画> --label original
python scripts/style_probe.py <AI生成图> --label generated
```

输出五个硬指标，**这是判断"像不像同一画风"的唯一客观依据**：

| 指标 | 说明 | 经验值（柔光二次元风） |
|---|---|---|
| 明度中位 V | 整体明暗 | **≥ 75%** |
| 高明度占比 (V>75%) | 高调程度 | **≥ 80%** |
| 饱和度中位 S | 浓淡 | **≤ 40%**，柔光风常在 10% 上下 |
| 低饱和占比 (S≤40%) | 干净程度 | **≥ 90%** |
| 主色 top1 + 色相 H | 识别特征 | **应与原画完全一致** |

再加两项**线条**指标（决定性，但常被忽略）：
- **线条颜色**：原稿多为**近黑**（`#000000`~`#1A1A2A`）。生成图若给出**彩色描边**（如深紫 `#303060`）→ 立刻不像。
- **线条像素占比**：原稿通常 **2~3%**（极细）。生成图占比大 = 粗描边 = 厚涂感。

### ③ 提示词写法

把②的数值直接写成硬约束，并**同时上传两张参考图**：

```
我上传了图1（原设，必须保留）和图2（原画风样板，画风必须匹配）。
画风必须严格匹配图2：
- 高明度：整体以白色和极浅色为主，暗部极少（明度 75~94%）
- 低饱和：饱和度不超过 40%
- 线条：极细的近黑描边。不要彩色描边、不要粗描边
- 阴影：只在关节/褶皱处柔和过渡，绝不要厚重阴影块
- 平涂为主 + 柔和空气刷过渡
绝对不要：厚涂、油画感、强明暗对比、大面积深色、赛博朋克暗调
```

**画风样板图怎么做**：把原贴图的**脸/皮肤/服装/头发**四块放大拼成一张 2×2 图，配中文小标题。这比只描述文字有效得多。

### ④ AI 出图 → 收图 → 批量筛查

用 ③ 的提示词在 AI 网页版出图。收图后：
```bash
python scripts/batch_scan.py <原贴图> <图片目录> --ref-bg alpha --picked <达标目录>
python scripts/split_grid.py <网格图> <输出目录>     # 2×2 拆图 + 量宽高比
```
**宽高比 > 0.6 就是被裁成半身**（正常全身 0.40~0.55），下半身缺失会导致鞋子等分区没参考。

### ⑤ 产出新贴图的两种方式（优先试 B）

| | **A. AI 逐区重绘** | **B. 贴图迁移（优先试）** |
|---|---|---|
| 做法 | 每个分区单独喂 AI 图生图重绘 | concept 图对应区域**按比例映射**到原贴图的 UV 岛，用岛的 alpha 做遮罩 |
| 需要用户 | ✅ 要（每区一次，或拼成任务图批量） | ❌ **零操作，全自动** |
| 原画保真 | 靠 AI 重画，可能跑偏 | **直接用 concept 的原画**，最忠实 |
| 风格一致性 | 需反复调 | **天然一致**（同一张原画） |
| 局限 | 慢、贵 | 窄处会拉伸；形状差异大时变形 |

**B 的做法（实测有效）**：
1. 用 ① 的着色诊断确证「岛 ↔ 部位」，别猜
2. 量出目标 UV 岛的 **alpha 包围盒**（不是区域框，是岛本身）
3. 取源框**按 concept 的人物包围盒归一化**（`fx, fy` 比例），这样同一套参数能适配不同画幅的稿子
4. `concept区域.resize(岛尺寸)` → `putalpha(岛的alpha)` → `alpha_composite` 贴回原位
5. 边缘 1~2px 高斯羽化避免硬边

**必须处理的细节（都是实测踩出来的）**：
- **手臂岛的底部是「手」**（肤色），不能迁移。用 `keep_bottom≈0.17` 只迁移袖子部分
- **裙子往往是独立岛**，不在身体岛里，别漏
- **⚠️ 取源框上沿别伸进下巴**（最隐蔽的坑）：领口岛的源框若吃到 concept 的**下巴/脖子肤色**，
  领子就被涂成肉色，渲染出来像「脸被拉长、多出一层下巴」。**实测两套稿都踩了**，
  且 V5 轻、V4 重，不易察觉 → 领口框的顶边要落在下巴以下
- **取源框下沿别伸进腿**：裙子框超出裙摆波浪线会把肤色糊到裙子上
- **不同 concept 的人物比例可能不同**（同一比例参数会错位）→ 用人物包围盒归一化 + 允许按稿覆盖
- **道具**（锤子/武器）若新设计里没有，直接把对应岛的 alpha 置 0 即可抹掉
- 脖子等**细窄区域**映射后会横向压缩，属可接受瑕疵

### ⑥ 验证：本地渲染 + 截图（不用装 Live2D 软件）

改完贴图必须**渲染看一眼**再交付，否则错位/糊色问题会直接交到用户手上。

```bash
# 1) 下载三个库（需代理）
#    live2dcubismcore.min.js  https://cubism.live2d.com/sdk-web/cubismcore/
#    pixi.min.js (6.x)        https://cdn.jsdelivr.net/npm/pixi.js@6.5.10/dist/browser/
#    cubism4.min.js           https://cdn.jsdelivr.net/npm/pixi-live2d-display@0.4.0/dist/
# 2) 写一个 HTML：PIXI.Application + PIXI.live2d.Live2DModel.from('模型.model3.json')
# 3) 用 python -m http.server 起本地服务（file:// 会被 CORS 拦）
# 4) 无头 Edge 截图
"C:/Program Files (x86)/Microsoft/Edge/Application/msedge.exe" \
  --headless=new --enable-unsafe-swiftshader --hide-scrollbars \
  --window-size=680,1000 --virtual-time-budget=18000 \
  --screenshot=out.png "http://127.0.0.1:8766/one.html?m=zipped"
```

**关键坑**：
- **居中要用 `getLocalBounds()` 而不是 `model.width`**。Live2D 模型画布往往远大于角色，
  用画布尺寸居中会把角色推到角落
- 无头模式必须加 `--enable-unsafe-swiftshader`，否则 WebGL 起不来（黑屏/空白）
- `--virtual-time-budget` 给足时间等模型加载
- **后台起的 http server 会自己死**，截图报 `127.0.0.1 拒绝连接` 就重启它，不是代码问题
- **不要给对照模型配 EyeBlink 分组**，否则截图可能正好抓到眨眼瞬间，误判成「眼睛坏了」

**⭐ 像素级自证（交付前必做）**：把「原模型」也渲染一张，跟新模型做 `ImageChops.difference`：
```python
diff = ImageChops.difference(orig, new).convert('L').point(lambda v: 255 if v > 26 else 0)
```
- 把差异像素涂红叠加在原图上 → **一眼看出到底哪些部位被改了**
- 这是回应「脸是不是坏了」这类质疑最有力的证据：只改衣服时，
  **脸部差异像素应该为 0**，变化区从颈部/锁骨以下才开始
- 也用来确认「该改的地方确实改了、不该改的地方一个像素没动」

### ⑦ 打包成 VTube Studio 可直接导入的模型

```
交付_OC模型/
  V5_关拉链高领/                ← 文件夹名即 VTS 里看到的分类
    OC_zipped.model3.json       ← 文件名即模型显示名
    OC_zipped.moc3
    OC_zipped.physics3.json
    OC_zipped.cdi3.json
    icon.png
    OC_zipped.2048/texture_00.png
  V4_敞开外套/
  导入说明.txt
```

- 直接复制原模型的 `.moc3` / `.physics3.json` / `.cdi3.json`，只替换贴图
- **重命名后必须同步改 `model3.json` 里的 `FileReferences`**（Moc / Textures / Physics / DisplayInfo）
- **图标要重新生成**：原模型的 `icon.png` 还是旧设计，直接拷过去会让 VTS 里显示旧形象。
  从新模型的渲染图裁头部（256×256）最省事
- **不要自造 `HitAreas`**：它的 `Id` 必须对应模型里真实的 ArtMesh 名，乱写会让 VTS 点击区域错乱。
  原模型没有就不加，VTS 会退化为包围盒。
- `model3.json` 里补上标准眨眼分组，否则 VTS 里不眨眼：
  `"Groups":[{"Target":"Parameter","Name":"EyeBlink","Ids":["ParamEyeLOpen","ParamEyeROpen"]}]`
- **多套服装 = 多个文件夹**，网格相同只换贴图，表情/物理完全一致

**交付前跑一遍完整性检查**：引用路径可解析、贴图尺寸/mode 正确、
`moc3` 与原模型 **md5 一致**（证明只换了贴图没动模型）。



## 三、三大坑（都踩过）

### 坑 1：改过头（最常见的翻车）

用户说"改一下"，实际要的是**在原设基础上微调**，不是重新设计。

**正确姿势**：先列「原设清单」，标注 100% 保留；然后**只允许 3 处以内的微小改动**，并逐条写明"程度：轻微"。
输出前自检：**原设的识别元素还剩几个？** 掉了 2 个以上 = 改过头了。

### 坑 2：加外套/配件把明度砸了 ⚠️

加一件大件（外套/斗篷/大裙摆）是最容易毁画风的操作。

**铁律：大件的主体底色必须是白/极浅色**，颜色只作**细条和点缀**。
深色大件会让明度从 90% 掉到 40%，画风当场崩成"油画感"。

配色配比参考：主体白 `#F5F5FA`（大面积）／点缀色（细条）／高光荧光（极细线）／小徽章圆点（极小）。

### 坑 3：腿/手等部位被"重设计"

AI 容易自作主张给光腿套上渐变紧身袜、把手画成小团块。
**在提示词里显式写死**：`腿必须是光腿，白皙肤色，不穿任何袜子`、`五指结构清晰可辨`。
肤色要**均匀**，禁止渐变和发光效果。

## 四、迭代技巧

### ⚠️ 坑：要"全身"就别用 2×2 网格出图

让 AI「一次出 4 个变体排成 2×2 网格」能省操作，但**每格接近正方形，装不下 1:2.2 的全身立绘**，
模型会自动**裁掉下半身**（只画到腰或大腿）。实测：网格出的 4 张宽高比全是 0.75，
而正常全身立绘应是 **0.40~0.55**。

**判断裁切的方法**（见 `scripts/*`，或自己量）：`宽高比 = 宽 / 高`，>0.6 基本就是半身。

**正确说法**：`请生成 4 张【独立的】图片，不要拼成网格；每张都是完整全身，宽高比约 1:2.2`。
宁可多等一会，也别拿到一批半身图——下半身（裙摆/鞋）是贴图必需的分区。

### 其他技巧

| 症状 | 处方 |
|---|---|
| 画风偏厚涂/油画 | 单发一条"提明度、压饱和、细线、删阴影"的修正指令 |
| 某部位画错 | **单独发一条只修那个部位的指令**，不要重开整图 |
| 需要多角度 | 拿满意那版说"用这个角色的设定，再画侧面/背面" |
| 为拆图做准备 | `正面站姿、双臂自然下垂不遮挡身体、纯白背景` |

AI 网页版**没有固定 seed**，同一提示词多刷几版挑最好的。

**素材交接**：把每轮要提交的文件收进一个**编号排序的固定文件夹**（如 `<项目>/上传包/01_xxx.jpg`），
并附一份**可直接复制**的纯文本提示词 + 说明。素材一变就重跑打包脚本刷新，
别让用户自己翻目录找文件。

## 五、抓官方美术参考图

需要参考某部作品的角色设计时：
- **JS 渲染的新闻页抓不到 `<img>`**（如 bushiroad.com/media/*）→ 改抓静态资源路径
  - 官网主题图：`<site>/wordpress/wp-content/themes/<theme>/assets/images/...`
  - 上传图：`<site>/wordpress/wp-content/uploads/YYYY/MM/...`
- 需要**开代理**（`HTTP_PROXY`/`HTTPS_PROXY`），脚本内 `ProxyHandler` 显式走代理 + `User-Agent`/`Referer` 伪装
- 商品页（`/discographies/<id>/`）常含封面原图，是最佳设计参考源


**推荐用法**：
```bash
# 拆分区 + 认部件
python scripts/part_segment.py 贴图.png out/
python scripts/island_diagnostic.py 贴图.png uv/            # → debug_texture.png
```

`batch_scan.py` 的 `--ref-bg` **必须选对**：原贴图用 `alpha`，普通插画用 `auto`。
参考图选错（例如拿带深色背景的宣传图）会让全部分数失真。

**拼回时注意**：重绘件尺寸若与 box 不符会自动缩放，但缩放会引入模糊并可能让 UV 对齐偏移——
**优先在重绘阶段就保持原尺寸**，必要时用 `--strict-size` 强制报错。
