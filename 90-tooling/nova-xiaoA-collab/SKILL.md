# Nova × 小A 协作分工总纲

> **一句话**：小A 是**主力产出手**，Nova 是**定框架 + 验收 + 组装交付**的人。
> 用户用了 WorkBuddy 就**不想再切去 Antigravity IDE**——默认全流程在本会话内闭掉。

---

## 0. 为什么这样分工（用户原话，2026-09-27 确立）

> 「**大部分都要让小A来做，因为这样可以省我们这边的 credit**。」
> 「写完之后，**你来看一遍**。一般来讲它们写的都还不错，都不用改。
> 如果确实要改的话，**你跟我讲，我再告诉你怎么改**。」
> 「**CC 和 GPT 不是主力，Gemini 才是主力**好吗？CC 和 GPT **只有在有代码任务的时候才要用**，
> 其他的所有，一般来讲都是让 Gemini 来的。」（2026-09-27 用户纠正）
> 「我让你去调用小A……**一般来讲，我都不会想过去的，是想让你跟他联动一下**。」

**三条不可动摇的前提**：
1. **省钱驱动** —— 产出尽量外移给小A，Nova 只做必须由本会话完成的事（组装、核验、呈现）
2. **Nova 是质检关** —— 小A 写完 ≠ 完工；Nova 必须读一遍，**高质量就直过，要改先问用户**
3. **IDE 是被动选项** —— 用户不主动提，Nova 提都不提

## 1. 分工决策树（核心）

```
任务进来
  │
  ├─ 需要「动手写东西」吗？（代码 / 文案 / 报告 / 分析稿 / 算法）
  │     │
  │     ├─ 需要联网搜最新信息？──────► 自己干（小A 联网弱，且省一轮往返）
  │     ├─ 需要看/改本会话已有的文件状态（如刚生成的 docx 里某段）？
  │     │                              ──► 自己干（小A 看不到我们的中间产物）
  │     ├─ 只是几十行以内的零碎脚本 / 一次性小工具？
  │     │                              ──► 自己干（派活成本 > 收益）
  │     │
  │     └─ 否则（成块的代码 / 成篇的文案 / 成体系的分析）
  │                                    ──► **派给小A**⭐（默认动作）
  │
  └─ 纯组装 / 排版 / 格式核验 / 把已有素材拼成交付物？
        ──► 自己干
```

**默认倾向**：**模糊时倾向派给小A**（用户明确要省 credit）。

## 2. 模型选择顺序（🔴 以此为准）

用户 2026-09-27 明确：

| 优先级 | 模型 | 什么时候用 |
|---|---|---|
| **1（默认主力）** | **Gemini（`gemini-3.8-flash-high`）** | **一切非代码任务**：文案、分析、报告、资料整理、学习材料……**默认就用它** |
| **2（仅限代码）** | **Claude Code（`claude-*`）** 优先，其次 **GPT（`gpt-oss-*`）** | **只有任务是编程/代码类**时才切过去 |

> 🔴 用户原话：「**CC 和 GPT 不是主力，Gemini 才是主力**。
> CC 和 GPT **只有在有代码任务的时候才要用**，其他的所有，一般来讲都是让 Gemini 来的。」
>
> **判定规则**：任务里**有没有真正写代码 / 改代码 / 调试程序**？
> - **有** → 代码任务 → CC（首选）/ GPT（兜底）
> - **没有** → 一律 Gemini
>
> ⚠️ 这条**推翻了 2026-09-27 之前我误记的版本**（我曾错写为「CC 优先、Gemini 兜底」）。
> 以本节为准。

> ⚠️ **额度现实**：`claude-*` 与 `gpt-oss-*` **共享同一个额度池**，Gemini **独立池且额度最多**。
> 这进一步印证「Gemini 当主力」的策略——非代码任务不去碰那两个共享池。

**连带注意**：
- Gemini 仍受 Google 账号地区判定影响，偶发 `User location is not supported` → **换节点无效**，直接换 CC/GPT 即可
- 用 Claude 时**不要带 `--effort`**（不支持）

## 3. 派活标准动作（五步，缺一不可）

### ① 拆步（硬约束）
- 一步 = **读 1-2 个文件 + 写 ≤100 行**
- prompt 里**明写输出行数上限**
- **串行执行**（并行会互相拖慢，实测并行 7min vs 串行 3min）
- 整个任务需要在 prompt 里带上「总步数 + 当前是第几步」，帮小A 建立全局视图

### ② 写 prompt（三层结构）
```
[背景指路]  先读 C:\Users\13662\.workbuddy\USER.md 的「小A背景包」X 节了解背景
[任务本体]  执行：<具体描述，含输入文件路径、输出文件路径、格式要求、行数上限>
[收尾要求]  产出要求：<写到哪里、什么格式>
```
- 背景依赖强（学习材料 / 论文 / 工作台）→ **指路 USER.md**，**绝不整段复述**（防漂移、防浪费 token）
- 纯技术任务（独立脚本 / 改 bug）→ 不指路，直接派

### ③ 串行派活（技术细节见 `antigravity-headless-bridge`）
```bash
agy -p="<任务>" --add-dir <目标目录> \
    --model <按第2节：非代码=Gemini；代码=CC/GPT> \
    --output-format json --print-timeout 600s > _r.json 2>&1
```
- ⚠️ **必须后台跑**（宿主 Bash 前台约 2 分钟超时，会 SIGTERM 杀掉长命令）
- ⚠️ **不要带 `--effort`**；模型档位用 ID 后缀（`-high`/`-medium`）控制

### ④ 验收（🔴 只看文件，不看 status）
```bash
ls -la <目标目录>          # 唯一可信的成功判据
```
- ⚠️ **`status` 会骗人**：实测有步骤返回 `status:ERROR` 但**文件完整落地**
- 也见过 `status:SUCCESS` + `response:""` + `denied_actions`（权限被拒，实际没干）
- 文件不在目标目录 → 去 `~/.gemini/antigravity-cli/scratch/` 找（漏了 `--add-dir`）

### ⑤ 汇报（每次必做，不得省略）
```
小A 已完成：<任务摘要>
模型：<model id>
耗时：<duration_seconds>s
用量：输入 X / 输出 Y / 思考 Z / 缓存读取 W / 合计 T
额度：headless 无法获取（请在 Antigravity 界面查看状态栏）
```
⚠️ **额度永远拿不到**（headless 不产出）→ **如实说明，绝不编造数字**。

## 4. 🔴 质检关：小A 写完 ≠ 完工

这是本技能**最重要的行为约定**，直接来自用户原话：

| 情况 | Nova 的动作 |
|---|---|
| 读完觉得**质量达标**（通常情况） | **直接采用**，不要画蛇添足去改、不要显摆自己的版本 |
| 读完觉得**确实要改** | **先跟用户说**「这里我建议改成 X，原因是 Y」，**等用户拍板**再动 |
| **绝不** | 擅自动手重写、擅自替换成自己的版本、把用户没要求改的地方改掉 |

**质检要读什么**：
- 逻辑是否自洽、有没有硬伤（数字、事实、引用）
- 是否符合任务的**格式要求**（行数、结构、术语）
- 是否符合用户既有偏好（见 USER.md）

**⚠️ 血泪教训（2026-09-27 实训报告）**：
我误判「角色分工表是自己加的」而删了它，实际那是**模板原有的内容**，用户不得不回来纠正。
→ **凡是「看起来像我生成的、但没确证来源」的内容，动手删改前先问用户**。

## 5. 🚫 IDE 触发条件（极严格）

**默认：不提 IDE。** 用户不主动提，Nova 就一个字都不说。

**唯一可提的两种情况**：
1. **用户主动问**「是不是要去 IDE 那边弄」→ 才解释
2. **死结**：WorkBuddy 做不到 **且** 小A headless 也调不通（例如需要重新登录 Google 账号、需要改 agy 配置），
   才说明「这个得你去 IDE 处理一下，因为 X」

**技术层能自愈的，一律自己搞定**（换节点、重试、换模型家族），**不要甩给用户**。

## 6. 交付物归属（用户 2026-09-24 明确）

小A 产出后，Nova **必须完整呈现**，不能只丢文件路径：

> 「小A做完之后，你要正常的像我在 WorkBuddy 用模型一样给我呈现出来，不能直接丢小A的文档。」

- **代码类**：贴出关键代码 + 讲实现思路 + 给运行结果
- **文档/报告类**：概述结构 + 贴核心段落
- **数据类**：展示关键数字与结论
- 最后用 `present_files` 把成品给到用户

**最终交付物永远是 Nova 的作品**，不是「小A 的文档」。

## 7. 与其它资产的关系

| 资产 | 职责 |
|---|---|
| **本技能** | 决定**派不派、派什么、怎么验收、IDE 何时提** |

| `<项目>/GEMINI.md` | 长期项目的**技术栈与结构约定** |

## 8. 快速自检清单（派活前扫一眼）

- [ ] 背景只指路、没复述吗？（背景依赖型任务）
- [ ] `--add-dir` 加了吗？没带 `--effort` 吧？

- [ ] 验收是 `ls` 文件而不是看 `status` 吧？
- [ ] 三项汇报（模型/耗时/用量）准备好了吗？额度如实说"拿不到"了吗？
