# 跨模型 / 跨会话的项目连续性机制

## 核心原理

切模型或压缩上下文时，**唯一可靠的信息载体是文件**。
对话历史会被截断、被摘要、被不同模型以不同方式理解——**不要指望它**。

因此：**每次实质工作后，把状态写进文件；新会话开场，先读文件再动手。**

## 三层结构（缺一层就会漏）

### 第 1 层：项目根 `HANDOFF.md` —— 全量状态书

⚠️ **是全量，不是摘要。** 用户最怕的就是"信息被压缩掉"。宁可长，不可省。

必备 9 节：

| 节 | 内容 | 为什么必须 |
|---|---|---|
| 0 一句话定位 | 项目在干什么 | 新模型 30 秒进入状态 |
| 1 **硬约束表** | 用户明令的不可违反项，编号 C1/C2/… | 最容易丢、丢了代价最大 |
| 2 权威数据与已核验数值 | 数据源路径 + 已验证的关键数字 | 避免重算、避免用错源 |
| 3 模型/结构 | 变量、路径、编号体系 | 避免改错结构 |
| 4 文件清单 + 备份链 | 每个文件是干什么的 + 回退路径 | 避免找不到/误删 |
| 5 关键操作姿势 | 易错操作的正确做法 | 避免重复踩坑 |
| 6 环境坑 | 本机特有陷阱 | 新会话必踩 |
| 7 当前状态 | 已完成 / 待办 / 未决（含"需用户拍板"的） | 直接知道下一步 |
| 8 关键决策记录 | 时间 + 决策 + 理由 | 避免推翻已定的事 |
| 9 **变更日志** | **追加式**，只加不删 | 就是"全部保留"的载体 |

### 第 2 层：工作区记忆锚点 `.workbuddy/memory/MEMORY.md`

工作区记忆是**系统会自动引用**的，所以它是最可靠的路标。
写三件事：**①"动手前先读 HANDOFF.md"的铁律 ②硬约束速查 ③环境速查**。
保持短——它是路标，不是正文。

### 第 3 层：每日日志 `.workbuddy/memory/YYYY-MM-DD.md`

**追加式**，记当天做了什么。跨天累积。超过 30 天再蒸馏进 MEMORY.md。

## 维护纪律（不遵守机制就失效）

1. **每轮实质改动后立刻追加**变更日志，不要攒着
2. **只追加不删改** —— 删改 = 主动丢信息，正好违背用户诉求
3. 待办清单里**明确标出"需要用户拍板"的项**，否则新模型会擅自决定
4. 备份链写进文件清单，让新会话知道能回退
5. HANDOFF 里可以直接**引用用户原话**作为约束依据 —— 比转述可靠

## 反模式

| 反模式 | 后果 |
|---|---|
| 把 HANDOFF 写成"摘要" | 用户要的恰恰是"全部保留"，摘要=丢信息 |
| 状态只存在 Obsidian / 外部笔记 | 模型读不到，等于没写 |
| 只写每日日志，没有项目主控文件 | 新会话要读十几个文件才能拼出状态 |
| 变更日志用"覆盖式更新" | 历史决策被抹掉，无法追溯 |
| 硬约束散落在正文里 | 新模型读到一半就动手，违反约束 |
| 待办里不标"待用户确认" | 新模型擅自拍板，返工 |

## 开场 checklist（新会话/新模型照做）

1. 读 `HANDOFF.md` 全文
2. 读工作区 `.workbuddy/memory/MEMORY.md`
3. 读最近 1–2 天的每日日志
4. 看 `paper\_修改记录.md`（或项目的变更记录）
5. **确认"当前状态 → 待办"与用户最新一条指令对齐**，再动手

## 附带能力：跨会话找回旧讨论

如果要找的是**几轮之前的具体讨论**（不在文件里），用 `conversation_search` 工具，
查询要自包含（描述在找什么 + 时间范围 + 背景），它搜不到当前对话。
