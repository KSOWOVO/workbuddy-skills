## 设计系统

**浅色默认**（Kelsen 指定）：浅蓝 `#4f8ef7` 主交互 + 浅粉 `#f7a8c9` 点缀 + 白/浅灰蓝 `#f7f8fc` 基底。
**深色对等打磨**：`[data-theme="dark"]` 覆盖为 `#0b0d12` 近黑基底。

- Surface 阶梯：`--sf / --sf2 / --sf3 / --sf4`；边框三档 `--bd / --bd2 / --bd3`
- 文字四级：`--tx / --tx2 / --tx3 / --tx4`
- 语义色：`--ac`(蓝) `--pk`(粉) `--gn`(绿) `--am`(琥珀) `--rd`(红) + 对应 `*S`(浅底) `*L`(线)
- 圆角：10 / 13 / 15 / 16 / 999px；阴影三档 `--sh1/2/3`
- 动效：一律 transform/opacity；`prefers-reduced-motion` 全局降级
- 版式：`.wrap` 1060px（列表页）/ `.wrap-narrow` 830px（阅读页）；正文 `.prose` 74ch / 1.85 行高

| 文件 | 职责 |
|---|---|

## 全文精要（`kb-essence.js`）★ 复习中枢

每篇文章顶部的核心区块。**设计前提：用户只复习这一块，不看下面的原文**，
所以它必须完整承载「逻辑 / 观点 / 看法 / 学习点」四件事。

```js
window.KB_ESSENCE = {
  "g13": {
    tldr:   "一句话总览，≤40字",
    logic:  [ { t:"环节名≤10字", d:"这一环讲什么≤40字" } ],  // 3-6 项，竖向步骤条
    points: [ "核心论断≤45字" ],      // 4-8 条 ——「文章说了什么」
    views:  [ "作者看法/态度≤45字" ], // 2-5 条 ——「作者怎么看」
    learn:  [ "学习要点≤45字" ],      // 4-8 条 ——「我该学什么」（绿勾清单）
    quiz:   [ { q:"问题", a:"答案要点" } ],  // 3-5 条 ——主动回忆，答案默认收起
    tags:   [ "关键词" ]
  }
};
```

**生产流程**（新增篇目时）：
1. `node _manifest.js` 生成篇目清单
2. **并行** spawn 若干 general-purpose 子代理，每批 6-12 篇，读 vault 原文后产出
   `_essence_b*.json`（实测 6 路并行 3-8 分钟跑完 51 篇，远快于串行）
3. `node _mkessence.js` 合并 + 校验（缺篇/多篇/字段缺失都会报出来）

**渲染**：`app.js` 的 `renderEssenceSection(it)`；样式在 `styles.css` 的 `.essence / .es-*`。
交互：点 `.es-qq` 单条揭晓；`#esQuiz` 一键展开/收起全部。

**⚠️ 设计教训**：早期做过「模糊原文」的自测，被 Kelsen 否掉 ——
原话「做这个有啥用啊？我又不用它来做些什么」。**动效必须服务于复习目的，不能为动而动。**

## 构建脚本

| `_archive.js` | 旧文件归档到 `_archive/` |

## 自动同步后端（server/）

`:8787` 静态托管 + `GET /api/status` + `POST /api/sync`。
**⚠️ 后端 `lib/build.js` 仍输出旧格式 `data.js`，与新版 `kb-data.js` 不兼容**——
若要恢复「浏览器点按钮自动同步」，需把 build.js 改为输出 kb-data 格式。
目前推荐用 `_parse.js` + `_mkdata.js` 两步脚本。
