# 数据造假指纹核验

## 核心判断原则

**先分层，再下结论。** 一次核验要分开回答两个完全不同的问题：

| 层 | 问题 | 看什么 |
|---|---|---|
| L1 采集层 | 这 300 份是真人填的吗？ | 时间戳分布、IP/设备分散度、废卷、直线作答、重复提交 |
| L2 文件层 | 我手上这份表是原始导出吗？ | 文件元数据、工作簿里有没有"加工流水线"表 |

**最常见的误判**：L1 干净就宣布"数据没问题"。但一份 L1 干净的数据，完全可以被人在 L2 层用脚本重写一遍再交付。两层必须分开给结论。

## 执行顺序

### 第 0 步：文件级指纹（先做，成本最低，定性最强）

```bash
python scripts/xlsx_probe.py "<文件路径>"
```

或手工看 `docProps/core.xml` + `docProps/app.xml`：

- `dc:creator` = `openpyxl` / `pandas` / `xlsxwriter` → **整个文件由脚本写出**，不是问卷平台原始导出（问卷星/腾讯问卷/Qualtrics 导出会带自己的生成器标识）
- `dcterms:created` 与 `dcterms:modified` 间隔 < 5 分钟 → 一次性脚本写出
- 附带的旁证：本机**未安装 openpyxl**，`pandas.read_excel` 会 `ImportError`。不要在这上面卡住，直接用 `scripts/xlsx_probe.py`（纯标准库 zipfile+xml）。若编辑器 MCP 报 `No workbook open` / `UNOPENABLE_LOCAL_PATH`，也走同一个脚本。

### 第 1 步：结构总览

列出所有工作表。**工作表名字本身就是证据**——如果出现这类表，说明这份文件是"加工现场"而非交付品：

`信度对比` `修改明细` `旋转载荷矩阵` `题项诊断` `假设检验保真` `指纹审计` `数据清洗记录`

### 第 2 步：L1 采集层体检（判"是不是真人填的"）

| 检查项 | 真人数据的特征 | 造假的信号 |
|---|---|---|
| 时间戳自洽 | 结束−开始 == 作答时长，全部一致 | 不一致，或时长是整十整百 |
| 时长分布 | 右偏长尾，有人挂页面挂几小时；有 < 30 秒废卷 | 压成窄带、无长尾、无废卷；唯一值远少于样本数 |
| 日期分布 | 有推广爆发日和断档 | 每天数量平滑均匀，像随机撒的 |
| IP | 段位分散，有少量合理重复（同一 wifi） | 全部唯一（太干净）；或大量同段位聚集 |
| 设备指纹 | 组合几十到上百种 | 只有个位数组合 |
| 整行重复 | 允许极少 | 严格 0 条也可能是脚本去重后的结果 |
| 直线作答 | 通常有几份全选同一个 | 0 份需警惕，但也可能被清洗掉了 |
| 答案分布 | 有偏态，社会赞许偏差常见 | 五点量表五项各占 20% —— 这是随机数生成器 |

### 第 2.5 步：跨字段物理一致性（最强的一类证据）

生成脚本往往**逐字段独立抽样**，字段之间就失去了现实世界里的约束。凡是问出"这在物理上可能吗"，就是杀招：

- **操作系统 × 分辨率**：`Windows` 配 `375px*667px` / `360px*800px` 这类手机视口 —— 桌面系统不可能。真实数据里 Android 只配 Android 分辨率、Windows 只配 1366×768/1920×1080。若 Windows 把手机分辨率**全都配了一遍**，基本坐实独立抽样。
- **经纬度 × 省市**：把同一城市的所有坐标求跨度。新加坡经度跨度只有 0.25°，若样本里"新加坡"的经度跨度 2.8°（≈315 km，已到马来西亚），就是假的。伦敦算出 86° 经度跨度 = 绕地球四分之一圈，直接判决。真人的 GPS/IP 定位必然落在所填城市附近。
- **IP × 地理位置**：看 IP 段聚集度与省份/城市是否对得上。
- **时长 × 题目数**：334 份全长 103~261 秒（极差比 2.53）且**峰度为负**（比正态还平）、无长尾、无废卷 —— 真人时长是强右偏对数正态，一定有几个挂机几十分钟的和几个 30 秒内乱点的。截断式分布 = 生成器在两个边界之间采样。
- **各题均值压缩**：25 道题的均值全部挤在 3.73~3.97（sd 仅 0.064）。真人回答不同措辞的题，均值差异会明显更大。这是按目标统计量反向生成的特征。
- **构念内相关过于整齐**：题间相关全部落在 0.52~0.70 一条窄带里，缺少真实数据必然出现的"某题相关特别高/特别低"。

**判断口径**：跨字段物理矛盾 ≥ 1 条 → 合成数据，无需再看其他。因为这类矛盾无法用"真人乱填"解释，只能用"字段独立生成"解释。

## 反向陷阱：别被"太干净"骗了

生成脚本常被设定为"通过审计"，于是刻意满足这些约束：

> 时间戳自洽（结束−开始 == 时长）、IP 全部唯一、无重复整行、无直线作答、量表单题分布正常

这几项**全部通过，恰恰是可疑的**。真实问卷多多少少会脏。当"干净得不真实"和"跨字段物理矛盾"同时出现时，前者是伪装，后者是实锤。

## 该看什么、不该看什么

**只看原始数据表（通常叫 Sheet1 / 数据 / raw）。** 附带的分析表（`信度对比`、`修改明细`、`指纹审计` 等）若被明确告知是噪音/装饰，直接跳过——它们可能是烟雾弹。所有结论必须能在原始表的列里独立复现。

### 第 3 步：L2 篡改痕迹（判"数据被动过没有"）

这是最致命的一类，一旦出现即可定性：

- **定向微调**：某张表记录了 N 个单元格的"原值→新值"，且**变动幅度高度统一**（例如 328 格全部只 ±1）。真实数据清洗不会只做 ±1 的最小扰动——这是为了让统计指标达标而做的定向优化。
- **精准卡阈值**：α 从 0.70~0.82 全部被拉到 0.80~0.85，**全部刚好越过 0.8**；KMO 刚好过 0.9。真实数据不会集体贴着阈值线站队。
- **改数据但不动结论**：β 系数变化全部 < 0.02，假设结论前后完全一致。说明改动的唯一目的是修饰信效度指标，不是修正数据。
- **自证矛盾**：出现一张 `指纹审计` 表写着"全部通过 / 可疑项：无"，但同一张表里自己的数字是"净改动格数 328 / 触及人数 197"。**审计表的结论和它自己的数据打架时，以数据为准。**
- **触及率**：被改动的样本占比。> 30% 就已属系统性篡改（本例 197/334 = 59%）。

## 输出格式（用户要快，不要长）

控制在 600 字内：

1. **一句话结论**（L1 和 L2 分开说）
2. **最可疑的 1–3 个证据点**，每条带具体数字
3. **这份数据能不能用**的建议

不要贴大段原始数据，不要罗列所有通过的检查项。

## 红线

- **只读**。任何情况下不修改、不保存被核验的文件。
- 不替用户把结论往"没问题"或"肯定造假"上推。证据分裂时就说分裂，并说明哪部分是硬证据、哪部分是弱证据。
- L2 有篡改痕迹**不等于** L1 数据是编的。两者独立，分别下结论。
